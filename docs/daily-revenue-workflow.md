# Daily revenue workflow: seven working days

Use the current app to close existing leads before deciding on another redesign. This is a measurement exercise, not a promise of increased sales.

## Twice a day

1. **Today → Reply now.** Open the Waiting view. Reading a conversation does not finish it. Start with the oldest waiting thread and check the contact, recipient and workspace sender number.
2. **Reply deliberately.** Use an AI draft only if helpful; review/edit before Send. If sending fails, keep the text and inspect the error before retrying. Queued is not delivered. Use Next waiting reply to continue.
3. **Approvals.** Clear legitimate pending approvals using the existing review flow. Do not approve unwanted or non-consensual outreach just to empty a queue.
4. **Appointments.** Confirm upcoming appointments and work the existing cancellation/rescheduling recovery flow.
5. **Pipeline.** Update actual next steps and won/lost outcomes. Record a win only when the deal is won, not merely when someone replies or books.

Keep a short friction note when work stalls: what you were trying to do, the delay category, approximate time lost and whether the UI showed a recoverable error. Do not include phone numbers, transcripts, emails or customer names in a shared tracking sheet.

Compare similar lead sources, campaign mix, eligibility and time windows. A low-volume week is inconclusive. Write down changes in lead quality or volume that could explain a result independently of the UI.

## What to build next

- **Enough leads, slow manual response:** improve queue handling or targeted shortcuts based on the notes.
- **Response is prompt, bookings are weak:** inspect the offer/message/booking transition before changing the inbox layout.
- **Bookings happen, attendance or wins are weak:** inspect confirmation and pipeline follow-up using the existing screens.
- **Little incoming demand:** acquisition, targeting and the offer are the bottleneck; another dashboard is unlikely to solve that.
- **Actual measured slow screens or delivery failures:** reproduce the slow/failing path and measure it before choosing an optimization.

## Search and draft limitations

Search names, phone numbers or the latest message preview; a full email can match exactly. Partial-email and full-history searches are not implemented. The initial thread view shows at most 100 recent messages and identifies that limit.

Drafts are temporary, workspace/thread-specific text, not server-saved records. They survive switching within the inbox but should not be treated as durable notes. Send, explicitly discard, or copy important text before closing the browser. Saved views preserve filters/search preferences, not message bodies.

Daily use and tracking require real operating activity over time. The code pass cannot complete that seven-day evaluation or establish revenue improvement in advance.
