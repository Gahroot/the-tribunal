# Prompt CI snapshots

Place each proposed voice prompt version in a JSON file here with `system_prompt` and optional `initial_greeting` string fields. Do not put customer transcripts, credentials, or personal information in snapshots. The CI workflow runs all eight simulated callers against every snapshot and blocks a score below 0.80, a scenario-specific failure, an uncertain judgment, or any judge error.

Database-only prompt edits cannot be inspected by GitHub CI. The runtime system-approval path checks candidates before creating a version, the auto-promotion worker checks tested candidates again before replacing the live version, and the experiment worker gates statistical winners before activating them; human approvals remain manual.

Historical replay samples up to 50 nonempty voice transcripts from the last seven days, including versions that are no longer active. Workspace ownership is checked in the sampling query. It uses the same rubric and scenario-behavior judges as simulations; a judge error produces a failed verdict and does not skip the remaining calls. The worker logs call IDs, pass/fail, scores, counts and average score—not transcripts or free-text reasons, which may quote personal information. Replayed history measures prior performance, **not** how a proposed prompt would have answered. Model processing follows the existing transcript-judgment provider path.

The replay worker runs at startup and approximately weekly thereafter (the shared worker loop adds jitter). Restarts repeat the sample; run a single worker process to avoid duplicate replay and model charges. This is not a durable calendar scheduler.

The simulation is text-only and cannot verify actual audio, accent comprehension, voicemail detection, or tool side effects. No telephony or messaging tools are exposed; `message_test_worker.py` sends real messages and is deliberately not used for offline simulation. The former `roleplay_worker.py` is absent in this checkout; interactive practice lives in `app/services/ai/roleplay/`. Each scenario has a 120-second deadline, and provider/judge errors fail closed while the remaining scenarios continue. Oversized prompts fail instead of silently evaluating a truncated version.

Run locally from `backend/`: `uv run --frozen python -m scripts.dev.prompt_scenario_gate prompts/<snapshot>.json`. Every scenario prints PASS/FAIL, score and reason; any failure returns exit code 1, even when later snapshots pass. Empty snapshot lists fail closed. This directory currently contains no exported customer prompt snapshots: add sanitized snapshots of the versions being changed to exercise the live CI gate. The workflow also supports manual dispatch.

The live CI gate needs `OPENAI_API_KEY` configured as a GitHub Actions repository secret. Without it, the job fails closed. Pull requests from forks cannot access the secret and also fail closed; run trusted prompt changes from branches within the repository. Live model calls incur API usage. Existing prompt versions stored only in the database must be exported as snapshots for a CI prompt-change gate; do not export real transcripts.
